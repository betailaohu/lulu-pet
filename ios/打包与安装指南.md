# iOS 打包与安装指南（iPhone 17 / iOS 26.6.1）

## 先说清楚一件事

**这台工作机是 Windows，编不了 iOS。** `.ipa` 必须由 macOS + Xcode 产出，没有例外（不是配置问题，是工具链不存在）。

所以「出一个 iOS 包」这件事拆成两半：

- **出包**：在 GitHub 的 macOS 机器上跑（不用你有 Mac），产物是**未签名** `.ipa`
- **装机**：在你的 Windows 上用自己的 Apple ID 重签，再装进 iPhone 17

本指南把两半都写死，照着做就行。

---

## 第一步：把工程推到 GitHub（只需一次）

仓库已经在本地初始化并提交好了（`.gitignore` 也配了，`.research/templates`、`dist/`、构建产物都不进库，实际只有 ~3 MB）。你只需要建个空仓库再推上去：

```bash
cd F:/手机桌宠
git remote add origin https://github.com/<你的用户名>/lulu-pet.git
git push -u origin main
```

> 私有仓库也行，Actions 在私有仓库同样有免费额度（macOS runner 消耗 10 倍分钟数，这个工程单次约 5–8 分钟）。
> `.github/workflows/ios-build.yml` 推上去就会生效。

## 第二步：跑 iOS Build

GitHub 页面 → **Actions** → 左侧 **iOS Build** → **Run workflow**。

- 第一次跑建议先不勾 `strip_app_group`，出包再说
- 跑完在页面底部 **Artifacts** 下载 `LuluPet-unsigned-ipa`
- 解压得到 `LuluPet-unsigned.ipa`（约 20–30 MB，含 36 张立绘）

workflow 做的事：装 XcodeGen → 从 `shared/` 同步素材 → `xcodegen generate` → `xcodebuild -scheme PetApp -configuration Release CODE_SIGNING_ALLOWED=NO` → 把 `.app` 塞进 `Payload/` 打 zip。

> 用的是 GitHub 上的 `macos-latest`，会自动挑最新的 Xcode。如果你的设备是 iOS 26，建议 runner 上是 Xcode 26；workflow 里有一步会打印 `xcodebuild -version`，跑完看一眼就知道用了哪版。

## 第三步：在 Windows 上签名安装

需要两个东西，都是一次性安装：

1. **Apple Devices**（微软商店搜 "Apple Devices"，微软官方那个）—— 提供 iPhone 的驱动与设备通信
2. **Sideloadly**（<https://sideloadly.io>）—— 用你的 Apple ID 给 ipa 重签

操作：

1. iPhone 用数据线连电脑，手机上点「信任此电脑」
2. 打开 Sideloadly，`iPA` 处拖入 `LuluPet-unsigned.ipa`，`Apple ID` 填你的 Apple ID
3. 点 **Start**，输入 Apple ID 密码（如果开了双重认证，要在弹窗里填一次验证码）
4. 装完后在手机上：**设置 → 通用 → VPN 与设备管理 → 开发者 App → 信任**
5. 首次运行会提示开发者模式：**设置 → 隐私与安全性 → 开发者模式 → 打开 → 重启手机**

### 免费 Apple ID 的三个硬限制

| 限制 | 说明 |
| --- | --- |
| **7 天过期** | 每 7 天要用 Sideloadly 重签一次，否则图标点开就闪退。想要长期用要么 99 美元/年开发者账号，要么每 7 天重签 |
| **最多 3 个自签 App** | 同时装着超过 3 个会装不上，删一个再装 |
| **拿不到 App Groups** | 免费账号不支持 App Groups 能力，**桌面小组件读不到主 App 的养成数值**，会一直显示默认快照（立绘 + "噜噜正在发呆"）。主 App 内一切正常 |

第三点如果 Sideloadly 直接报 `Provisioning profile doesn't support the App Groups`，回到 Actions 重新跑一次，**勾上 `strip_app_group`**，用新包再签。代码里已经做了兜底：`AppGroup.defaults` 在拿不到 suite 时退化为 `.standard`，App 不会崩，只是小组件不联动。

## 第四步：把桌宠放到桌面

1. 长按桌面空白处 → 左上角「+」→ 搜「水豚噜噜」→ 选小号/中号 → 添加
2. 中号会显示饱食度 / 心情两条进度条，小号只显示立绘 + 一句状态
3. 锁屏小组件：长按锁屏 → 自定义 → 添加小组件，支持圆形、矩形、内联三种
4. 灵动岛：主 App 里点一下噜噜（`pat`）就会起一个 Live Activity，30 分钟后自动过期。**Apple 的规则是 Live Activity 表示"进行中的临时事件"，不能做常驻**，所以它是"陪一会儿"而不是"一直在"

## 如果要改配置

`shared/manifest.json` 和 `shared/state.json` 是双端唯一事实源。改完：

```bash
python assets/lulu/sync_assets.py      # 同步图片 + 配置到 Android 和 iOS
```

然后重跑 Actions（`ios/**`、`shared/**` 有改动会自动触发）。

## 本机没验证过的部分

Swift 代码是盲写的，虽然把已知的坑都按 Xcode 26 的规则改过了（`containerBackground`、`SWIFT_VERSION` 合法值、`Combine` 显式导入、scheme 显式声明），但**没跑过一次真编译**。第一次 CI 如果报错，把 `ios/build.log` 里的错误贴出来即可，通常是个别 API 签名细节。

已经在代码里规避的几个典型编译错误：

| 坑 | 处理 |
| --- | --- |
| `SWIFT_VERSION: "5.9"` 不是合法值，swiftc 直接报 invalid value | 改成 `"5.0"`（语言模式，与编译器版本无关） |
| iOS 17 起小组件必须用 `containerBackground` | 已替换，否则运行时报错并且背景异常 |
| `ObservableObject` / `@Published` 来自 Combine | `PetState.swift` 显式 `import Combine` |
| CI 里 `-scheme PetApp` 找不到 scheme | `project.yml` 里显式声明 scheme |
| 扩包编进了 AppIcon 会报图标缺失 | widget target 排除 `Assets.xcassets` |
| `public` 嵌套在 internal 类型里 | 去掉 `public` |
